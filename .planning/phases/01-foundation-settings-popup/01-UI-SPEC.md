# Phase 01 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Covers:** UI-01, UI-02, UI-03, UI-04, UI-05 — plus the two UI surfaces CLEAN-01 and FOUND-04 push into the popup (the toggle row, the selector-miss warning row).

**Scope of this contract:** the **extension popup** (`entrypoints/popup/`, its own document, no shadow root) and the **shared token layer** (`assets/tailwind.css`) that the Phase 1 dev-only shadow-root probe and every later phase's injected surface will import. Phase 1 ships no user-visible injected UI — CLEAN-01 hides nodes via one stylesheet and an attribute, it renders nothing. The shadow-root portal provider (FOUND-06) is proven by a probe that `exclude: ['production']` keeps out of the shipped build (CONTEXT D-02), so it carries no visual contract beyond "the tokens below reach it."

**Quality bar (from CONTEXT.md `<specifics>`):** *"Toggling it feels native, not bolted on."* Every value below is chosen to match X's own rendering rather than to express a separate brand. This extension has no brand of its own inside the popup.

The table below is a **non-exhaustive** list of known-good components for this phase, never a closed allowlist. Reaching for a component outside it is the expected path, not an exception.

| Component | Import path | Notes |
|-----------|-------------|-------|
| Switch | `@/components/ui/switch` | The only control type in Phase 1. One per feature toggle. `checked` + `onCheckedChange` writes straight to storage — there is no Save button anywhere in this extension |

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside a tile; tooltip arrow offset |
| sm | 8px | Tile grid gap; gap between a toggle label and its info icon; warning row internal padding |
| md | 16px | Popup horizontal page padding; panel row vertical padding; header/footer horizontal padding |
| lg | 24px | Gap between the grid and the header rule; empty-state internal padding |
| xl | 32px | Empty-state vertical padding (top and bottom) |
| 2xl | 48px | Not used in Phase 1 — reserved |
| 3xl | 64px | Not used in Phase 1 — reserved |

**Fixed structural dimensions** (derived from the scale, all multiples of 4 — these are layout constants, not spacing exceptions):

| Element | Value | Why exactly this |
|---------|-------|------------------|
| Popup frame | `360 × 480` fixed | Chrome caps popups at 800×600. **Fixed both axes is load-bearing**: D-03 swaps the grid for a panel inside the same window, and a popup that resizes mid-swap reads as a bug, not a transition |
| Header row | 48px tall | Holds the back chevron (32×32 hit area) + category name |
| Footer row | 40px tall | Version string + "Report an issue" |
| Content viewport | 392px tall, `overflow-y: auto` | `480 − 48 − 40`. Both the grid and every panel scroll inside this, so the header and footer never move |
| Category tile | `104 × 104` | `(360 − 16·2 page padding − 8·2 gaps) ÷ 3` |
| Grid columns | 3 | Locked. Phase 1 renders one tile; it sits top-left and the row is not centred or stretched — later phases fill in beside it |
| Toggle row | 48px min height | Comfortable mouse target; matches the header so the two read as one rhythm |
| Back chevron hit area | 32 × 32 | Icon glyph 20px, centred |

Exceptions: none. Every value above is a multiple of 4.

## Typography

X renders tweet text at 15px, secondary metadata at 13px, and section headings at 20px/700. This contract copies that scale exactly rather than inventing one, because "matches X" *is* the requirement.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px | 400 | 1.5 (22.5px) |
| Label | 13px | 400 | 1.4 (18.2px) |
| Heading | 20px | 700 | 1.2 (24px) |
| Display | 12px | 400 | 1.4 (16.8px) |

**Four sizes: 12 / 13 / 15 / 20. Two weights: 400 and 700.** No 500, no 600 — Chirp ships 400/700 as its workhorse pair and X uses 700 (not 600) for headings; a 600 request synthesises or snaps and reads subtly wrong.

Role assignment, unambiguously:

| Surface | Role |
|---------|------|
| Toggle title ("Hide promoted tweets") | Body — 15/400 |
| Toggle description + tooltip body | Label — 13/400 |
| Tile caption ("Timeline") | Label — 13/400, centred, max 2 lines |
| Panel header category name; empty-state heading | Heading — 20/700 |
| Footer version string; footer link | Display — 12/400 |
| Selector-miss warning row | Label — 13/400 (**not** bold — see Color: emphasis comes from the tinted surface and the icon, not from weight) |

The "Display" role is the smallest size, not the largest. The popup has no display type; the row is spent on footer metadata so the scale stays at four declared sizes rather than three plus an undeclared one.

### Font resolution — two mechanisms, one family name

Every surface declares the identical stack:

```css
font-family: "TwitterChirp", -apple-system, BlinkMacSystemFont, "Segoe UI",
             Roboto, Helvetica, Arial, sans-serif;
```

That fallback chain is X's own, copied verbatim, so the degraded case still matches X's degraded case.

**Shadow-root surfaces (Phase 1 probe; Phases 2–5 real UI): free.** x.com declares `@font-face` for `TwitterChirp` at document level, and document-level font faces *do* pierce into shadow roots. Only `@font-face` declared **inside** a shadow root is ignored by Chromium (`issues.chromium.org/issues/41085401`) — so never declare one there; just name the family.

**Popup: requires the cached-URL mechanism.** The popup is a separate document on the extension origin with no access to x.com's font faces. The contract:

1. The content script reads the `TwitterChirp` `@font-face` `src` URL out of the page's own stylesheets / `document.fonts` and caches it into `local:xTheme` alongside the theme values.
2. The popup, on mount, injects its own `@font-face { font-family: "TwitterChirp"; src: url(<cached>) format("woff2"); font-weight: 400 700; font-display: swap; }`.
3. With no cached URL (fresh install, popup opened before ever visiting x.com), the fallback stack renders and nothing else changes. `font-display: swap` guarantees text is readable throughout; there is **no** blocking state and **no** spinner for font load.

Three constraints this mechanism must respect:

- **Do not bundle a Chirp file.** Chirp is proprietary (commissioned from Grilli Type). Shipping the binary inside a Chrome Web Store package is a licensing exposure with no upside.
- **Do not add an `extension_pages` CSP override to make this work.** Chrome's default MV3 extension-page CSP constrains `script-src`/`object-src` only, so a remote font loads without any manifest change. A CSP override in the manifest is a review flag for zero benefit — if this appears to be needed, the diagnosis is wrong.
- **Phase 6 must carry this in the privacy narrative.** The request is a font asset fetched from X's own CDN (`abs.twimg.com`), carrying no user data, to a domain the user is already on. STORE-03's claim — *no user data is transmitted* — stays true. But it is the **one** outbound request this extension makes, and the privacy policy must name it rather than let a reviewer find it.

> ⚠️ **Flagged for user sign-off.** `01-RESEARCH.md` § "X's Chirp Font (UI-04)" escalated this as the single point in the phase where "feels native" trades against a network request, and asked for explicit confirmation. This contract picks the option that actually satisfies UI-04 and success criterion 1 ("rendered in X's Chirp font"). **If the user prefers zero outbound requests, drop steps 1–3 and keep the fallback stack alone** — the popup then matches X's *fallback* rendering exactly, which is a defensible but literal-miss reading of UI-04. Nothing else in this spec changes.

## Color

**No color in this popup is a fixed value.** UI-03 requires the popup to match X's active theme, and X ships two web schemes today (Default, Lights Out) after removing Dim in February 2026 — with Dim possibly alive in some cohorts. Every color is therefore a CSS variable resolved at runtime from the cached probe, with a hardcoded fallback. **Never write a three-way `'light' | 'dim' | 'lightsOut'` enum** (RESEARCH Pattern 8): derive from the observed value, branch `unknown` to `prefers-color-scheme`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bt-bg)` → `#FFFFFF` light / `#000000` lights-out | Popup body, panel background, content viewport |
| Secondary (30%) | `var(--bt-surface)` → `#F7F9F9` light / `#16181C` lights-out | Category tiles, header bar, footer bar, tooltip surface, warning-row tint base |
| Accent (10%) | `var(--bt-accent)` → `#1D9BF0` both schemes | See reserved-for list below |
| Destructive | `var(--bt-destructive)` → `#F4212E` both schemes | **Unused in Phase 1** — declared so later phases do not invent a second red. Phase 1 has no destructive action |

Supporting tokens (not part of the 60/30/10 split — they are text and edges, not surfaces):

| Token | Light | Lights Out | Usage |
|-------|-------|------------|-------|
| `--bt-fg` | `#0F1419` | `#E7E9EA` | All primary text, all icon glyphs |
| `--bt-fg-muted` | `#536471` | `#71767B` | Label-role secondary text, footer version, tile caption when its tile is not hovered |
| `--bt-border` | `#EFF3F4` | `#2F3336` | Header rule, footer rule, tile border, row dividers |
| `--bt-warn` | `#E07C00` | `#FF9500` | Selector-miss icon + action-badge dot **only**. Never a text color — `#FF7A00` on white is ~2.9:1 and fails AA |

**Accent reserved for:**

1. The ON state of a `Switch` (track fill + focus ring).
2. The keyboard focus ring on a category tile, the back chevron, and the footer link (2px ring, 2px offset).
3. The footer "Report an issue" link text.

That is the complete list. The accent is **not** used for: tile icons (they are `--bt-fg`), tile backgrounds, the panel header, hover states, or the warning row. Phase 1's popup shows exactly one blue element at rest — the single ON switch — which is what keeps the 10% honest at a 360×480 canvas.

**Dim cohort:** if the probe reports a background this contract does not map (e.g. `rgb(21, 32, 43)`), the scheme is `unknown`, the popup falls back to `prefers-color-scheme`, and **nothing visibly breaks**. Do not add a third hardcoded palette to chase it.

**Value provenance.** `#1D9BF0` (`rgb(29, 155, 240)`), `#FFFFFF`, `#000000`, and `rgb(5, 5, 5)` are `[VERIFIED: control-panel-for-twitter@4.24.1]` via `01-RESEARCH.md` Pattern 8. The surface, foreground, muted, border, and destructive values are **seed values from X's published palette and must be verified against live x.com during the theme spike** — they are the fallback constants, so a wrong one degrades the popup's fidelity without breaking it.

**Contrast floor:** every text/background pair above clears WCAG AA 4.5:1 for Body and Label roles in both schemes. `--bt-fg-muted` on `--bt-surface` is the tightest pair in each — re-check it, not the obvious ones, if a value changes.

## Copywriting Contract

Voice: **plain, first-person-plural-free, no exclamation marks, no marketing.** This is a personal tool the author also ships publicly; the popup should read like a settings screen, not like an onboarding flow. Sentence case everywhere, including buttons and headings. Never "Oops", never "Something went wrong".

| Element | Copy |
|---------|------|
| Primary CTA | **"Report an issue"** — footer link, opens the GitHub issues page in a new tab. This phase has **no submit-style CTA by design**: toggles write to storage on change and apply live (FOUND-07), so there is no Save button, no "Apply", and no confirmation toast anywhere in the popup |
| Empty state heading | "No settings yet" |
| Empty state body | "Features add their own settings here. If this screen is empty, the extension didn't load properly — reload it from chrome://extensions." |
| Error state | **Selector miss (D-09, FOUND-04):** heading "Not matching X's current layout" · body "X changed its markup, so this toggle isn't finding anything right now. Everything else still works." · action "Report an issue" |
| Error state (secondary) | **Settings unreadable:** heading "Couldn't load your settings" · body "Your settings live in this browser. Close and reopen the popup — if this keeps happening, reload the extension from chrome://extensions." |
| Destructive confirmation | **None.** Phase 1 has no destructive action. Turning "Hide promoted tweets" off is instant and lossless (D-06 hides by attribute, never by removing a node), so a confirmation would be friction with nothing behind it. Later phases must not add one here by analogy |

### Named strings (verbatim — the executor copies these, does not paraphrase)

| Key | String |
|-----|--------|
| Category tile caption | "Timeline" |
| Panel header (same category) | "Timeline" |
| Toggle title | "Hide promoted tweets" |
| Toggle tooltip (UI-05) | "Hides ads and promoted posts from your timeline as it loads, including ones that appear while you scroll." |
| Footer version | `v{version}` — e.g. `v0.1.0`, read from the manifest, never hardcoded |
| Back control accessible name | "Back to all settings" |
| Action badge tooltip (browser toolbar) | "One feature isn't matching X's layout" |

### Tooltip contract (UI-05)

- **Every** feature toggle carries one. A toggle registered without tooltip copy is a defect, not a default — the feature registry (D-01) should make the field required so a later phase cannot forget.
- One `TooltipProvider` at the popup root, `delayDuration={400}`, `skipDelayDuration={200}`.
- Trigger: an `Info` (lucide) glyph at 16px, `--bt-fg-muted`, 8px after the toggle title — **not** the whole row, so hovering to reach the switch never fires a tooltip.
- The trigger is a real focusable `button` with `aria-label="What does this do?"` prefixed by the toggle title, so the tooltip is reachable by keyboard and not mouse-only.
- Content: `side="top"`, `sideOffset={8}`, `max-width: 260px`, Label role (13/400), `--bt-surface` background, `--bt-fg` text, 1px `--bt-border`, 8px radius, 8px padding.
- **No `container` prop.** The popup is its own document; Radix portals to its `body` and works. FOUND-06's shadow-root provider must **not** be imported here — it is dead indirection in this surface and copying it in sets a wrong precedent for Phases 2–5.

## Layout & Interaction Contract

Not in the base template; included because the executor cannot build D-01 through D-03 from tokens alone.

### Grid view (UI-01)

```
┌──────────────────────────────── 360 ─┐
│ header 48   "Better Twitter"    [!]  │  no back chevron at grid level
├──────────────────────────────────────┤
│ 16 padding                           │
│  ┌──104──┐ ┌──104──┐ ┌──104──┐       │  3 cols, 8px gap
│  │ icon  │ │       │ │       │       │  icon 24px, --bt-fg, centred
│  │Timeline│ │       │ │       │      │  caption 13/400, 8px below icon
│  └───────┘ └───────┘ └───────┘       │
│                                      │  content viewport 392, scrolls
├──────────────────────────────────────┤
│ footer 40   v0.1.0    Report an issue│
└──────────────────────────────────────┘
```

- Tile: `--bt-surface` background, 1px `--bt-border`, 12px radius, centred column (icon over caption, 8px gap).
- Tile hover: background lifts one step toward `--bt-fg` (light: `#EFF3F4`; lights-out: `#1D1F23`), caption goes `--bt-fg-muted` → `--bt-fg`. No scale transform, no shadow — X does not use either.
- Tile is a `button`, not a `div` with `onClick`. Focus ring is the accent, 2px, 2px offset.
- **No greyed-out "coming soon" tiles** (D-02). A category with zero registered features does not render.
- One tile in Phase 1 sits top-left in a normal 3-column grid. Do not centre it, stretch it, or special-case the single-tile layout — the grid is meant to fill up.

### Panel view (UI-02, D-03)

- The **same** 360×480 frame. Only the content viewport swaps.
- Header becomes: back chevron (32×32, `ChevronLeft` 20px) + category name at Heading role (20/700), left-aligned, 8px gap.
- Each feature renders as a 48px-min row: title (Body) + info trigger on the left, `Switch` right-aligned, 16px horizontal padding, 1px `--bt-border` divider between rows (not after the last).
- Row is **not** clickable. Only the switch toggles. A whole-row click target next to a switch produces accidental flips.
- A row whose feature id appears in `local:diagnostics` (D-09/D-10) gains a warning strip directly beneath it, inside the same row block: `--bt-warn` `AlertTriangle` at 16px, then the error copy at Label role in `--bt-fg` on a 10%-alpha `--bt-warn` tint, 8px padding, 8px radius. The switch stays interactive — the feature is broken, not disabled, and locking the user out of their own setting helps nobody.
- No nested levels. No separate options page (D-04 / deferred).

### Navigation transition

- Grid → panel and panel → grid: 120ms opacity cross-fade plus a 4px horizontal slide (panel enters from the right, grid from the left). Ease-out.
- `@media (prefers-reduced-motion: reduce)`: swap instantly, no opacity animation, no transform.
- Scroll position resets to top on every view change.
- Browser back does nothing here (there is no router) — the back chevron is the only way out of a panel, which is why it is always present in the panel header.

### First paint (the flash problem)

The popup's theme comes from an **async** `chrome.storage` read, so a naive implementation paints the wrong scheme for one frame. Contract:

1. `assets/tailwind.css` defines both palettes under `@media (prefers-color-scheme: light)` / `(dark)`. This is **synchronous** — first paint is already plausibly correct with zero JS.
2. On resolve, the cached X theme overrides the variables on `:root`. For the common case (X theme agrees with the OS), nothing visibly changes.
3. The shell (header, footer, grid frame) renders immediately. Switches render in position but `disabled` until settings resolve — typically under one frame. **No spinner, no skeleton shimmer, no layout shift.** A 360×480 surface that flashes a loading state looks broken in a way that a 40ms disabled switch does not.
