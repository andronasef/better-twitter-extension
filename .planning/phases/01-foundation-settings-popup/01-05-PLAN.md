  <behavior>
    - `usePortalContainer` inside a provider returns the provided shadow root.
    - `usePortalContainer` outside any provider returns `undefined`, not `null`, so the consuming Radix portal falls back to its documented default and the component renders rather than throwing.
    - A wrapper rendered inside a provider passes the shadow root through to its Radix portal's container prop.
    - Two wrappers open simultaneously inside one provider both mount their content under the provided shadow root.
    - The outside-interaction handler treats an event whose composed path includes the shadow root as inside, and one whose composed path does not as outside.
  </behavior>
  <action>
Generate the two remaining primitives this plan needs: run `pnpm dlx shadcn@latest add popover dropdown-menu`. Do **not** add `dialog` or `sheet`. Every open upstream shadow-DOM issue — focus trap, scroll lock, outside interaction — concentrates in `Dialog`'s paths, and this phase has no need that requires one. Setting that precedent now is how Phases 4 and 5 avoid inheriting the hardest case.

Create `components/shadow-portal.tsx` holding a React context carrying the `ShadowRoot`, exporting `ShadowRootProvider` and `usePortalContainer`. The hook returns the context value coerced to the element type Radix's `container` prop expects, or `undefined` when there is no provider. Returning `undefined` rather than `null` is deliberate and load-bearing: `undefined` lets Radix apply its own documented default, so a component used outside a shadow root still renders. The popup depends on exactly this — it is its own document, passes no container at all, and must not import this provider.

Create shadow-safe wrappers under `components/shadow-ui/`: `BtPopover`, `BtDropdownMenu`, and `BtTooltip`. Each composes its Radix primitive and passes `usePortalContainer()`'s value to the portal's `container` prop. The wrappers are the enforcement mechanism, not a convenience: a portal without a container renders into the page body, outside the shadow root where the injected stylesheet lives, and appears as unstyled text in the page's default font floating over the timeline. Routing every injected overlay through a wrapper means no individual component has to remember the rule, and the rule becomes assertable in one place.

Pass the `ShadowRoot` itself, never the shadow **host**. WXT's shadow-root UI object exposes both: the shadow root is the node performing the isolation and the host is the element added to the page whose styles are explicitly not isolated. Passing the host puts portalled content in the page's unstyled DOM — the same failure the container prop exists to prevent, arrived at one step later.

Override outside-interaction detection in each wrapper. Radix's default reasons about the document's active element, which from outside a shadow boundary only ever reports the host, so dismissal misfires. Handle the pointer-down-outside event by reading the originating event's **composed path** — the only event API that traverses shadow boundaries correctly — and preventing the default dismissal when that path includes the provided container. Apply this in the wrapper, so every consumer inherits it.

Write `tests/unit/shadow-portal.test.tsx` covering every bullet in the `<behavior>` block, including the no-provider `undefined` case and the composed-path inside/outside discrimination. Write the tests before the implementation and confirm they fail first. Note in a comment at the top of the file that these tests cover the provider's wiring contract only: jsdom does not implement enough of the real DOM's shadow, portal, and focus semantics to catch the focus-trap and scroll-lock bugs the open upstream issues describe, which is what the probe in Task 2 and spike S3 exist for.
