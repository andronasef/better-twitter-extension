**Goal line is not in user-story format.** The ROADMAP `**Goal:**` for Phase 1 reads:

> "The extension installs on x.com, presents a working icon-grid settings popup, and promoted tweets disappear the instant the user flips a toggle — proving the whole settings → pipeline → DOM → live-toggle chain on the lowest-risk feature."

Per MVP-mode rules a user story is never invented by the planner. Run `/gsd mvp-phase 01` to convert the goal line to "As a … I want to … so that …" if the story framing is wanted; nothing in this plan depends on it.

<objective>
Stand the project up from nothing and prove the entire settings → pipeline → DOM → live-toggle chain works end to end on one real feature.

Purpose: This is the Walking Skeleton. Every architectural decision in `SKELETON.md` is made real here, and every later phase plugs into contracts this plan defines. Output: A loadable MV3 extension whose popup toggle makes promoted tweets vanish from a live feed with no reload.
</objective>

<!-- This plan CREATES these contracts. They are written here so Plans 02-05 and Phases 2-5 build against them without exploring the codebase. -->

`lib/storage.ts` — three WXT `storage.defineItem` items, each versioned from v1:
- `settingsItem: WxtStorageItem<{ version: number; features: Record<string, boolean> }>` at key `local:settings`, fallback `{ version: 1, features: { hidePromotedTweets: true } }`
- `diagnosticsItem: WxtStorageItem<Record<string, { selector: string; firstSeen: number }>>` at key `local:diagnostics`, fallback `{}`
- `xThemeItem: WxtStorageItem<{ backgroundColor: string; scheme: 'light' | 'dark' | 'unknown'; seenAt: number } | null>` at key `local:xTheme`, fallback `null`

`lib/registry.ts` — the shape every later feature registers against (D-01):
- `type FeatureEntry = { id: string; categoryId: string; title: string; tooltip: string; defaultEnabled: boolean }` — `tooltip` is **required**, so a later phase cannot register a toggle without explanatory copy (UI-SPEC tooltip contract)
- `type CategoryEntry = { id: string; caption: string; icon: LucideIcon }`
- `categories: CategoryEntry[]`, `features: FeatureEntry[]`, `featureDefaults: Record<string, boolean>` derived from `features`
- A category renders only when at least one feature is registered under it

`lib/selectors.ts` — the only file in the repository containing selector strings:
- `SELECTORS: Record<string, readonly string[]>` — each name maps to an ordered candidate chain
- `resolve(name: keyof typeof SELECTORS, root?: ParentNode): Element | null` — walks the chain in declared order, returns the first candidate's first match, returns `null` on total miss, never throws
- `resolveAll(name, root?): Element[]` — same chain walk, returns the first matching candidate's full node list

`entrypoints/x.content/pipeline.ts` — the single shared observation pipeline (FOUND-01/02):
- `startPipeline(ctx): void` — attaches one `MutationObserver` with `{ childList: true }` and no `subtree` to the resolved timeline
- `onTweetSeen(cb: (el: Element, tweetId: string) => void): () => void` — subscribe, returns an unsubscribe
- `onTweetGone(cb: (el: Element) => void): () => void`
- `replayKnownTweets(cb): void` — re-emits every currently-known tweet in document order, so a feature enabled mid-session catches up

`features/<id>/index.ts` — the feature controller contract every later phase implements:
- `{ id: string; init(): void; teardown(): void }`
</interfaces>
